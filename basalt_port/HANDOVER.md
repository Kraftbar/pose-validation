New float Eigen 3.4.0 (SSE, packet = 4) facts, all measured (`probe1.cc`, `probe2.cc`, `bs_lie_test.cc`):
- `Matrix3f * Matrix3f`, `Matrix3f * Vector3f`, `Vector3f::squaredNorm()`, `Vector3f::dot()`: every sum is `x0 + (x1 + x2)` (tree). No packet fits 3 rows (Matrix3d differs: rows 0-1 left fold as a 2-lane packet, row 2 tree; `Vector3d::squaredNorm` / `dot` are the left fold `(x0 + x1) + x2`).
- `Vector4f::squaredNorm()` / `Quaternionf::norm()` / `coeffs().normalize()`: `(x0^2 + x2^2) + (x1^2 + x3^2)` (same shape as double), then `sqrt` and elementwise `/ length` (a division, not a multiplication by the reciprocal).
- `Matrix6f * Matrix6f` (6+6+6 < 20, lazy coefficient product): rows 0-3 of every column are a 4-lane packet, a left fold `((p0 + p1) + p2) + ...`; rows 4, 5 are scalar coefficients `(p0 + (p1 + p2)) + (p3 + (p4 + p5))`. There is NO per-column alignedStart toggle (an earlier model that toggled 0 / 2 failed 14,045 of 20,000 computeRelPose Jacobians). `Matrix6d`: all rows packets, left fold. `-A * B` = `(-A) * B` bit-exactly (sign flips are exact).
- A product with a zero-diagonal factor (`hat * hat`, `hat * R`) hides the sum association (the three terms contain one exact zero), so call sites alone cannot validate the 3x3 rule; the oracle tests dense operands directly.
- `Matrix * (1 - cos(x)) / n2` is elementwise `(h * s1) / n2` (two roundings, division kept), `matrix / 2` is a division by the converted scalar, `J -= expr` is `J - expr` per element.
- Sophus `SO3 * SO3` and `SO3::inverse()` go through `SO3(QuaternionBase)` and so re-normalise every result (`length = sqrt(sqn4)`, `coeffs /= length`); `SO3::exp` does not normalise; `SE3::inverse` = `invR * (t * Scalar(-1))`; `SE3 * SE3` = `(a.so3 * b.so3, a.t + a.so3 * b.t)`;
  `SO3 * Vec3` = `p + w * uv + cross(q.vec, uv)` with `uv = 2 * cross(q.vec, p)` evaluated as `(p + w*uv) + c` per element.
- `Quaternion::toRotationMatrix`, `FromTwoVectors` (non-antipodal branch) are scalar code, transcribed as is. `float` literals: `Scalar(1.0 / 48.0)` is a double constant cast to float, `Scalar(0.5) * x` a float multiplication; no implicit double promotion occurs anywhere in these functions except the `epsilonSqrt` / `M_PI` comparison above.
- libm: `sinf`, `cosf`, `atan2f`, `sqrtf` / `sin`, `cos`, `atan2`, `sqrt` of the C code agree with the reference binary (glibc 2.39, same machine) in all 28 M compared values; gcc fuses sin/cos of the same argument into `sincos` in the reference with no value change.

Float Eigen 3.4.0 (SSE, packet 4, no FMA) rules measured for this module (every one is an oracle statement test; the first guesses that were wrong are listed):
- GEBP (mr = 8, nr = 4) for the 9-row products (`rows+depth+cols >= 20`, nested `F*cov` and `d_state_d_*` included): rows 0..7 are ONE left fold from k = 0, written `0 + 1*acc`; the remainder row 8 in a 4-column panel (columns 0..7) uses
  the swapped-traits path with 4 accumulators over `k mod 4` (k < 4*(depth/4)), `C0 = (C0+C1)+(C2+C3)`, then the leftover k sequentially; column 8 (leftover column) a scalar left fold. Depth 3 (`A*D*A^T`) collapses to a left fold.
- `dst = X * Y * Z.transpose()` as an ASSIGNMENT (also inside the 3-term sum of `integrate`) evaluates the OUTER product as the transposed problem: the swapped-chain pattern moves to output column 8 (rows 0..7), row 8 is a plain left fold
  (as noted for double in okvis_port/HANDOVER.md). The inner `F * cov_` is plain. Model: `gemm_fold_T`. Without it 615 / 1,422 `integrate.cov` steps mismatch.
- A (Large,1,Small) product (`d_state_d_bg_ * (bg - bg_lin)`, 9x3 * 3x1) is `CoeffBasedProductMode`, not GEMV: rows 0..7 two 4-lane packets `((p0 + p1) + p2)` with no leading `0 +`, row 8 a scalar `p0 + (p1 + p2)`. A 9x9 * 9x1 (`sqrt_cov_inv * res`) IS the column-major GEMV
  (per row left fold from 0, then `res + alpha*acc`); in `linearizeImu` that product is evaluated through the GEBP shape model `gemm_fold` with one column, which reproduces it exactly (tested).
- LDLT (`ldlt_inplace::unblocked`, Lower, 9x9, first-max diagonal pivoting incl. the lower-triangle swap, `temp = diag.asDiagonal() * A10^T`, `a_kk -= (A10*temp)` as a `dot` left fold WITHOUT the leading 0, the 1-row case `A21 -= A20*temp` as `dot`,
  rows >= 2 as GEMV `acc * alpha + res`, `A21 /= pivot` true division) and `triangular_solve_matrix<OnTheLeft, UnitLower>` of a 9x9 RHS (SmallPanelWidth = max(mr,nr) = 8: an 8-wide column-oriented panel `r -= b*l`, then the 1-row GEBP remainder
  `res + (-1)*acc` through the swapped 4-chain path for columns 0..7 and a left fold for column 8, then a 1x1 panel): bit-exact on 20,000 random matrices.
- 9-vector `squaredNorm()` (`(S*res).squaredNorm()`): lane-wise `s[i] + s[4+i]`, `predux = (l0 + l2) + (l1 + l3)`, then `+ s[8]`. 3-element reductions `a0 + (a1 + a2)`. `Vector3f / float` and `Matrix3f / int` are true divisions.
- `SO3(quaternion)` (every `*`, `inverse()`) re-normalises: `len = sqrtf((x*x + z*z) + (y*y + w*w))`, `coeffs /= len`; `exp` does not. `0.5 * accel_world` (double literal) is a float 0.5f; `Scalar(1e-9)` is `(float)1e-9` applied to `(float)dt_ns`.
- ODR hazard (PLAN.md 4d): the oracle includes `double_sphere_camera.hpp` first so that `compute_sqrt_cov_inv<float>` resolves to float `sqrt` (`sqrtss`, `1.0f / sqrtf(d)`), as in the reference's linearisation TUs (checked in the runner).
  A double-sqrt variant (`cvtss2sd; sqrtsd; divsd`) is NOT ported; as a mutation it differs on 16,634 / 273,737 comparisons.

Validation (tolerance 0, memcmp; `bs_imu_test`): 6 seeds x 20,000 scenarios (1,098,713 - 1,112,692 comparisons each, 0 mismatches), seed 7 under ASan+UBSan (277,706, 0), seed 8 at -O3 (1,100,925, 0), `prim` 20,000 matrices (200,000, 0),

   keypoint = (j, i-1) with response = score, kept iff the score is strictly greater than the 8 neighbours (rows i-2, i-1, i from three rolling buffers). So `bs_fast9_16` is a plain scalar formulation; the SIMD-specific skips (`j -= 8 / 16`) only skip lanes without candidates. Valid for threshold 0..127 (SIMD casts it to char).
   Keypoint order = rows ascending, x ascending (row r is emitted when row r+1 is done).
